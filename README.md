# Pollenkarte Hamburg

Shows today's pollen forecast for Hamburg together with the allergy-relevant street trees (birch, alder, hazel, ash) around you. Grasses, rye, mugwort and ragweed are part of the forecast too; they have no map layer because no register records them.

**Live:** https://hamburg-pollenkarte.vercel.app

- **Pollen forecast:** Deutscher Wetterdienst (DWD), region "Geest, Schleswig-Holstein und Hamburg"
- **Trees:** Straßenbaumkataster Hamburg (Urban Data Platform, `api.hamburg.de`)

Only street trees are included; trees in parks, gardens and forests are missing. This is orientation, not medical advice.

## Data

`public/data/trees/` holds one compact file per genus (`birke`, `erle`, `hasel`, `esche`) plus `meta.json` with source, licence and counts. Each tree is `[lon, lat, speciesIndex, plantYear, crownDiameterM]`; `0` means unknown.

```bash
npm run data:trees   # download and rebuild the tree files
npm test             # unit tests (no network)
```

The script follows the API's paging, retries temporary errors, checks that every page was received and refuses to publish a genus that shrank by more than 20 %. Files are only rewritten when the data changed. A GitHub Action (`update-trees.yml`) runs it on the 3rd of every month and commits changes to `main`; the city updates the cadastre once a year.

Tree data: Freie und Hansestadt Hamburg, Straßenbaumkataster, [Datenlizenz Deutschland – Namensnennung – 2.0](https://www.govdata.de/dl-de/by-2-0).

## Pollen API

`GET /api/pollen` (Vercel function `api/pollen.js`, logic in `lib/pollen.js`) returns the DWD forecast for the partregion "Geest, Schleswig-Holstein und Hamburg":

```json
{ "updated": "2026-10-11 11:00 Uhr", "region": "Geest, Schleswig-Holstein und Hamburg", "stale": false,
  "days": [{ "date": "2026-10-11", "levels": { "Birke": { "code": "2-3", "step": 5, "label": "mittel bis hoch" }, "...": null } }] }
```

- The DWD's "today" means the day of its last update (around 11:00), so every forecast carries a real date and the app picks the entry for the current day.
- `step` is 0–6 in half steps; `null` means the DWD gave no forecast (`-1`).
- Cached for an hour; if the DWD is unreachable the last good data is returned with `stale: true`.

```bash
npm run dev        # http://localhost:3000 (static files from public/ plus /api/pollen)
npm run dev:demo   # same, with spring example values instead of the live forecast
```

Pollen data: Deutscher Wetterdienst, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.de) ([terms](https://www.dwd.de/copyright)).

## App

`public/` is the whole frontend, without a build step:

```
public/
  index.html, css/app.css
  js/app.js      wiring and state
  js/config.js   tree genera and herbs, colours, shapes, season calendar
  js/data.js     forecast for the current day, tree loading, radius counts (tested in Node)
  js/map.js      MapLibre map: density heatmap, tree markers, radius
  js/ui.js       HTML building blocks for the panel, including the pollen clock
  js/search.js   address search (combobox)
  vendor/        MapLibre GL JS 4.7.1 (BSD-3-Clause), served from this site
  fonts/         Literata (SIL Open Font License, see fonts/OFL.txt)
  data/trees/    generated by scripts/fetch-trees.js
api/pollen.js    Vercel function
```

The address search uses the city's official address service (`POST https://api.hamburg.de/addr_search`, the same one the Hamburg geoportal uses). It knows streets and house numbers, returns WGS84 coordinates and allows cross-origin requests, so the browser queries it directly; no search text goes to Google or other third parties.

Zoomed out, a heatmap in the colours of the pollen clock (faint green = few, ochre to rust = many trees) shows where the selected trees cluster; from street level on each tree is a marker in its genus colour and shape. Trees whose pollen is not in the air today are dimmed.

When none of the chosen pollen types is in season and nothing is flying, the panel shows a "Pollenpause" with the next usual start (e.g. "Birke und Esche blühen meist ab März, in rund 5 Monaten.").

## Automated checks

- **Tests** (`test.yml`): `npm test` on every pull request and push to `main`.
- **Tree data** (`update-trees.yml`): monthly refresh, commits only when the data changed.
- **Branch rule**: a repository ruleset requires the `test` check before anything lands on `main`, so changes go through pull requests (auto-merge waits for the check). Only deploy keys may bypass it: `update-trees.yml` pushes with the write deploy key stored in the secret `TREES_DEPLOY_KEY`.
- **Live check** (`healthcheck.yml`): daily at 10:15 UTC (after the DWD update), `scripts/healthcheck.js` loads the live page, `/api/pollen`, the tree data and the external services the browser uses (basemap.de, the Hamburg address search). A failed run triggers GitHub's e-mail. The address comes from the repository variable `HEALTHCHECK_URL`; until it is set the job is skipped. Locally: `node scripts/healthcheck.js http://localhost:3000`.

## Deployment

Vercel: import the GitHub repository with the default settings ("Other" framework, no build command). `vercel.json` sets `public/` as the output directory and the cache headers; `api/pollen.js` becomes a serverless function. Afterwards set the repository variable `HEALTHCHECK_URL` to the production URL to enable the daily live check.

Page views are counted with Vercel Web Analytics (cookieless). `index.html` loads `/_vercel/insights/script.js` on every host except localhost; the script only exists once Analytics is enabled in the Vercel project (Analytics tab → Enable).

## Design drafts

`entwuerfe/` keeps the four drafts that led to the design (`npm run drafts`, http://localhost:8080). They load MapLibre from a CDN and use a data snapshot; they are not part of the app.

`entwuerfe/design/` holds the three visual directions that came after it: A Sichtfeld (pollen grains under the microscope), B Pollenuhr (a year ring after the DWD's phenological clock, chosen for the app) and C Schriftgewicht (the weight of the name as the gauge). They reuse the app's modules, tree data and pollen API, so they are served from the project root (`npm run drafts:design`, http://localhost:8090/entwuerfe/design/). Their fonts are under the SIL Open Font License, see `entwuerfe/design/fonts/`.
